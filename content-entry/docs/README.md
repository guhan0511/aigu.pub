# MD 文档更新入口

本目录是**唯一**的 Markdown 文档提交/更新入口。所有新增或修改的 md 文档都应放在这里，不要直接散落在仓库根目录。

## 分类存放逻辑

| 子目录 | 用途 | 现有文档 |
| --- | --- | --- |
| `site-content/` | 网站文案 / 内容填充类文档（给网站各页面提供文字、配图说明） | `content.md` |
| `guides/` | 操作指南 / 使用说明类文档（面向维护者的操作手册） | `visual-editing-guide.md` |

新增分类时，直接在本目录下创建新的子文件夹（如 `notes/`、`changelog/`），并在上表补充一行说明。

## 命名规则

- 统一使用小写字母、数字、连字符 `-`，不使用空格或中文标点：`xxx-yyy.md`
- 文件名需体现内容主题，例如 `homepage-content.md`、`travel-notes-2026.md`
- 同一文档的修订版本不单独建文件，直接在原文件内更新并通过 git 记录历史

## 提交更新流程

1. 确认文档归属分类（网站文案 → `site-content/`；操作指南 → `guides/`；其他 → 新建分类子目录）
2. 按命名规则新增或编辑 `.md` 文件
3. 文档中如需配图，使用 **[图片needed]** 标注，并在 [../images/README.md](../images/README.md) 对应分类目录上传图片，图片命名需与标注说明对应，方便后续关联
4. 提交前自查：标题层级、待填写占位符（如 `【待填写】`）是否已全部处理
5. 本地确认无误后再提交 / 同步给相关负责人；涉及网站正文更新的文档，由维护者据此手动更新对应的站点 html 页面（本目录内容不会被网站自动读取）

## 注意事项

- 本目录内的文档**不参与网站构建**，仅作为内容来源与归档，网站实际展示内容在仓库根目录的各 `.html` 页面中
- 请勿在网站根目录直接新建/存放 md 文档，统一走本入口
